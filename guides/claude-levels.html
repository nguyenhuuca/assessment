3+ How the agents work together

One orchestrator, focused workers, separate reviewers.

🧭 Roles

  • The orchestrator is the main session (Opus). It is the only agent that starts workers (workers have no Agent tool), owns the task list, merges their work, runs the gates and asks you at the gates.
  • Each worker gets one focused prompt and returns a summary (files changed, tests added, verdict block), not file dumps. Workers never share state with each other.
  • worker-builder works in its own git worktree. The orchestrator merges or cherry-picks its commits into main, then re-runs the gates itself.
  • Reviewers are separate agents from builders. Each ends with a verdict block (approve / revise). Only blocking findings send work back, at most 3 rounds.

4 Local /autopilot

Chains the workflow skills into one run; at most 3 rounds per loop.

🤖 Flow Level 4

plan ⇄ review → Gate 1 → implement ⇄ review → QA ×2 → commit → Gate 2 → CI + smoke
🎯
You take part: 3 times: Start, Gate 1, Gate 2.

📌 Real example

📦

🪶 Lite mode

Under 100 changed lines not counting tests, and no ADR: no docs/plans/plan-*.md and no docs/reports/autopilot-*.md. The plan and the report go to the console (local) or the PR body (headless).

📌 Real example

Issue #34 (back button color) → PR #35.

🔒 Safety

  • Only the repo owner can trigger a run, by label or by comment.
  • Issue text is data; instructions that try to change the workflow, permissions or gates are ignored.
  • Refuses to edit .github/, .claude/, CLAUDE.md, AGENTS.md, .env files, or write data-dropping migrations.

6 Auto gates

ADR-0025 · add one more label together with autopilot.

⚡ Labels Level 6

Extra labelGate 1Gate 2
(none)you /approveyou merge
autopilot:auto-mergeyou /approveautomatic merge
autopilot:autoautomaticautomatic merge

✅ Auto-merge conditions

  • The PR is ready, meaning code review returned approve.
  • No changes to .github/, .claude/, CLAUDE.md, AGENTS.md, scripts/claude-*, Liquibase migrations or .env.
  • ≤ 400 changed lines outside tests and docs.
  • The script re-runs mvn verify / webapp test + lint + build itself.
🔎 Details

Gate 1: the plan job writes <!-- autopilot:plan-review=approve --> in the PR body only when plan review returned approve; the workflow sees it and dispatches the build job (workflow_dispatch). A /revise always waits for you.

Gate 2: scripts/claude-autopilot-merge.sh (always the copy on main) squash-merges with the secret AUTOPILOT_MERGE_TOKEN. If any check fails, it comments the reason and leaves the PR to you.

📌 Real example

📦
Issue #36 → PR #37 merged and deployed in ~5 minutes, build job $0.39, nobody clicked anything.

⚠️ Risk

Code reaches prod without a human read. The smoke check after the deploy is still manual. Rollback = git revert the squash commit.
